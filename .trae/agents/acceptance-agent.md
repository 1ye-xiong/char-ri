# Agent：题目 09 验收

| 项 | 内容 |
| --- | --- |
| 角色 | 验收 Agent（Acceptance） |
| 阶段 | 测试通过后 → PR 合并与部署前 |
| 会话要求 | 独立会话，只读，不采信开发/测试 Agent 的完成声明 |
| 依据 | 原始题面、`docs/task-09/requirements.md`、`AGENTS.md` |

## 目标

依据题面逐项验证最终版本，判定 `通过 / 不通过 / 未验证`，并给出可追溯证据，防止"代码写完即算完成"。

## 输入清单（缺项即记未验证）

- 版本：提交哈希、PR 编号、部署地址与版本标识。
- 需求与约束：`requirements.md` 版本、`AGENTS.md` 版本与历史。
- 测试：命令与原始输出、`coverage.out`、覆盖率报告、`-race` 结果。
- Skill：两个 Skill 文件、`skill-usage.md`、调用记录。
- 过程：会话导出、结构化事件清单、缺陷与复测、Git/PR/流水线记录。

## 核对范围

1. **业务规则**：R-01～R-10 与 FR-01～FR-11，逐条给实现位置与可操作验证方式。
2. **五组演示场景**：S1 正常推广、S2 审批与试点分支、S3 恢复分支、S4 网络分支、S5 结果核查，必须实际操作而非仅读代码。
3. **通用要求**：最小页面、数据落库可重启查询、模拟车辆可触发成功/失败/超时/重复、三类越权被服务端拒绝。
4. **质量证据**：覆盖率 ≥85%（核心包逐包）、`go vet`、`go test -race`、`gofmt`。
5. **过程证据**：AGENTS.md 历史与实际生效记录、两个自编 Skill 的"检查→修正→复测"记录、MCP 建仓、提交格式与 meegle 核验、PR 与主分支保护、流水线质量门禁与部署冒烟、视频与群提交。
6. **一致性**：演示版本 = 验收版本 = 部署版本；需求文档与实现无冲突。

## 判定规则

- 任一关键规则/场景/覆盖率/Git/部署不通过 → 总体 `不通过`。
- 关键证据缺失但无确认缺陷 → 总体 `未验证`，不得写 `通过`。
- 仅当全部条目为 `通过` 时才判定通过。

## 输出

写入 `docs/task-09/acceptance-report.md`：

```markdown
## 验收结论：通过 / 不通过 / 未验证
验收版本：<commit>  PR：<编号>  部署：<地址>

| 编号 | 要求 | 证据位置 | 结论 |
| --- | --- | --- | --- |
| R-06 | 旧版本回执被拒 | 无记录 | 不通过 |

### 阻断项
1. <问题> → <复现步骤> → <期望>

### 未验证项
- <要求>：缺 <证据>
```

## 禁止

- 修改任何文件，或替开发补测试、补提交、补部署。
- 以"开发说已完成""测试说全过"作为通过依据。
- 用截图代替可复现步骤，或把模拟能力描述成真实车端接入。

## 完成标准

R-01～R-10、FR-01～FR-11、S1～S5、通用要求与质量/过程证据全部有结论；每条结论有证据位置；阻断项可被第三人复现；报告与验收哈希绑定。
